# Gemini Usage and Cost Investigation

## Scope

This investigation covers the first Intelligent Terminal release that still includes Gemini CLI.
It uses the official Google Gemini CLI native ACP server and the official Gemini Developer API.
Agent Maestro is not part of the Gemini production or live-verification path.

The eventual migration from Gemini CLI to Antigravity is separate. No Gemini family identity,
wire schema, or pricing assumption is reused for Antigravity without a new investigation.

## Tested environment

| Component | Value |
|---|---|
| Gemini CLI | `@google/gemini-cli@0.51.0` |
| Package source | Microsoft-protected npm feed / Azure Artifacts |
| ACP command | `gemini --acp` |
| Protocol | ACP v1 over JSON-RPC 2.0 stdio |
| Authentication | Official Gemini API key through `GEMINI_API_KEY` |
| Maestro routing | Disabled / absent |
| Workspace | Synthetic, non-sensitive local workspace |

`0.51.0` was the newest stable version available from the internal feed. The feed's `latest` tag
pointed to `0.52.0-preview.0`, which was not selected for the first-version baseline.

Gemini CLI still accepts `--experimental-acp`, but marks it deprecated. Intelligent Terminal now
uses the official `--acp` flag in the Rust registry, Terminal launch builder, and Settings probe.

The live desktop verifier temporarily selects `gemini-api-key` authentication and disables Gemini
CLI folder trust only for its synthetic workspace run. It restores the user's Gemini settings
byte-for-byte afterward. The API key remains only in `%USERPROFILE%\.gemini\.env`.

## Official API versus Gemini CLI ACP

The Gemini Developer API and Gemini CLI ACP are different boundaries:

```text
Direct API caller
	-> Gemini generateContent or Interactions API
	-> full Google API response

Intelligent Terminal
	-> Gemini CLI ACP
	-> Gemini CLI provider/session logic
	-> Gemini generateContent streaming API
	-> Gemini CLI converts selected fields into ACP
```

Gemini CLI 0.51.0 ACP uses `models.generateContentStream`. It does not expose the new Interactions
API response object directly. The official API documentation recommends Interactions API for new
applications, but that does not change the ACP wire generated by this CLI version.

## Model selection

The authoritative ACP model set is `session/new.result.models.availableModels`. Gemini CLI 0.51.0
advertised:

```text
auto
gemini-3.1-pro-preview
gemini-3-flash-preview
gemini-2.5-pro
gemini-3.5-flash
gemini-3.1-flash-lite
```

Models not in this list are not used for ACP product development, even when the direct API supports
them or the CLI accepts them on the command line.

An explicit ACP launch with requested model `gemini-3.6-flash` was accepted as the session's
`currentModelId`, but the completed response identified the actual model as `gemini-3.5-flash` in
`_meta.quota.model_usage`. Intelligent Terminal must use actual `model_usage` attribution rather
than assuming the requested model executed.

The direct official REST alias `gemini-flash-latest` resolved to `gemini-3.6-flash` at capture time.
That alias is intentionally excluded from ACP fixtures because it was not ACP-advertised and the
official docs say `latest` aliases may be hot-swapped.

Gemini CLI 0.51.0 accepts the requested model on its launch command but does not implement the ACP
`session/set_model` method. It returns `Method not found` if WTA repeats the same selection after
`session/new`. WTA treats that startup-only error as non-fatal only when both the trusted family is
`gemini` and the initialize reporter is exactly `gemini-cli`. Runtime model switches and every
other provider continue to surface model-selection failures.

## Real official ACP result

Gemini CLI 0.51.0 did not send standard ACP `usage_update`. It returned token counts in private
prompt-response metadata:

```json
{
	"stopReason": "end_turn",
	"_meta": {
		"quota": {
			"token_count": {
				"input_tokens": 10270,
				"output_tokens": 9
			},
			"model_usage": [
				{
					"model": "gemini-3.5-flash",
					"token_count": {
						"input_tokens": 10270,
						"output_tokens": 9
					}
				}
			]
		}
	}
}
```

Observed session updates were message chunks, thought chunks, and available commands. Standard
`usage_update` count was zero. The configured API key did not appear in raw or parsed ACP wire.

Full local evidence is kept under the ignored directory:

```text
test/e2e/artifacts/real-gemini-acp/
```

The historical prototype displayed the private input/output counts. After the final team decision,
the deployed desktop path was reverified with Gemini CLI 0.51.0 and `gemini-3.1-flash-lite`: the
prompt completed and Usage stayed hidden because Gemini did not emit standard context/cost. The
verifier also confirmed that temporary settings, workspaces, backups, and Dev processes were
removed or restored.

## Direct API Usage result

A separate official `generateContent` call to `gemini-flash-latest` returned:

```json
{
	"modelVersion": "gemini-3.6-flash",
	"usageMetadata": {
		"promptTokenCount": 18,
		"candidatesTokenCount": 11,
		"thoughtsTokenCount": 118,
		"totalTokenCount": 147,
		"serviceTier": "standard"
	}
}
```

This proves the official API has richer Usage than Gemini CLI ACP 0.51.0. ACP projects only input
and output token counts; thought and total token counts are lost at the CLI ACP boundary.

The direct API result is stored separately as `gemini-flash-latest-api.sanitized.json` and is not
used as an ACP fixture.

## Final product decision

Gemini CLI ACP did not report cost amount or currency. The Gemini API free tier reports token usage
but no billed cost in the model response. Official pricing pages distinguish free and paid tiers,
but Intelligent Terminal does not combine token counts with a public price table or estimate USD.

The private quota evidence remains useful for investigation, but it is not ACP-compliant data for
the two selected product metrics. Intelligent Terminal therefore does not parse or display it.
Gemini shows Usage only if a future CLI emits standard ACP context-window data and/or monetary cost.

## Provider token matrix

| Provider | Context source | Cost source | First-version behavior |
|---|---|---|---|---|
| Claude ACP 0.59.0 | Standard `usage_update` | Standard `usage_update.cost` | Show context and reported cost |
| Codex ACP 1.1.2 | Standard `usage_update` | Not reported | Show context only |
| OpenCode 1.18.3 | Standard `usage_update` | Standard `usage_update.cost` | Show context and reported cost; trust reported currency |
| Gemini CLI 0.51.0 | Not reported | Not reported | Hide Usage |
| Copilot CLI | Not reported | Not reported | Hide Usage; future standard ACP works automatically |

Standard ACP turn token Usage is not enabled because the product does not display input/output.

## Gemini private adapter status

The Gemini module remains in the provider registry, but its private extractor is a no-op and trusts
no reporter IDs. The generic provider interface remains available for a future reviewed extension.

## UI decision

The Bottom Bar displays only context-window data and monetary cost:

```text
1024 / 8192 Tokens    0.004 USD
```

Agents that report neither standard metric keep Usage hidden.

## Security and data handling

- The Gemini API key stays in `%USERPROFILE%\.gemini\.env` and is never copied into fixtures,
	logs, command arguments, or repository files.
- Live tests use synthetic workspaces because free-tier content may be used to improve Google
	products under the applicable terms.
- The Usage parser performs no network or credential access.
- Raw wire is ignored by Git and scanned for credential markers and the configured key value.
- `GOOGLE_GEMINI_BASE_URL` is absent during official tests, preventing accidental Maestro routing.
